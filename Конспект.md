# Конспект выполнения тестового задания клиники

Задача — объединить месячные выгрузки ЕКМС, определить возрастную категорию и канал привлечения, посчитать уникальных пациентов по клиникам и начислить вознаграждения представителям. Главная часть решения — правильно выбрать уровень расчёта. В исходной выгрузке одна строка описывает услугу. Вознаграждение рассчитывается на уровне пациента за месяц. Для сводной нужен третий уровень: пациент внутри месяца, клиники и канала.

## 1. Что открыть и в каком порядке

Открой готовую книгу Excel и начни с листа «Итоги». Он показывает объём выгрузок, число пациентов, компенсации и выплаты. Затем посмотри «Сводная»: строки содержат клиники и каналы привлечения, столбцы — месяцы. На листе «Вознаграждения» видно, сколько начислено каждому представителю. Для объяснения конкретной суммы перейди на «Пациент месяц», найди нужный ID и месяц, затем проверь исходные строки на листе «ЕКМС».

«Уникальные» — подготовка для сводной. Каждая строка представляет одну комбинацию месяца, клиники, канала и ID пациента. «Параметры» содержит путь к папке выгрузок и справочные условия задачи. Менять нужно жёлтую ячейку B2 с путём. Числа с условиями ниже приведены для чтения; правила расчёта находятся в запросе «ПациентМесяц» и формулах.

## 2. Как прочитать задание до начала расчётов

Сначала выпиши сущности: пациент, услуга, клиника, представитель, месяц. Затем для каждого результата определи ключ группировки.

| Результат | Ключ | Что рассчитываем |
| --- | --- | --- |
| Объединённая ЕКМС | Файл и номер строки | Сохраняем строки услуг |
| Сводная посещений | Месяц, клиника, канал | Количество разных ID пациента |
| Расчёт выплаты | Месяц, ID пациента | Сумма компенсаций, категория, представитель, выплата |
| Выплата представителю | Представитель, месяц | Сумма выплат по пациентам |

ФИО пациента не подходит в качестве ключа: возможны однофамильцы, опечатки и лишние пробелы. Для задачи используется «id пациента». Полисы, диагнозы, телефоны и адреса не нужны для расчётов и не переносятся в рабочий набор.

## 3. Какие правила приняты в решении

Возраст берётся из поля «возраст» исходной выгрузки. Дробная часть сохраняется. Категория «взрослые» начинается с 18 включительно. Возраст 17,99 относится к детям. Округление перед сравнением может ошибочно превратить ребёнка во взрослого.

Канал определяется только наличием представителя после очистки пробелов: заполнен — «от Агентов», пуст — «Реклама». Поле «источник» для этого правила не используется: в задании дано другое условие.

Месяц определяется по дате услуги и хранится в виде YYYY-MM. Это позволяет различать август разных лет и правильно сортировать периоды. В исходных данных задания месяцы дат платежей совпадают с месяцами дат услуг. Если в следующих выгрузках появится отличие, для задачи про фактически полученные оплаты следует согласовать использование даты платежа и изменить месяц выплаты отдельно от месяца услуги.

Оплата пациента за месяц суммируется по всем его строкам, включая разные клиники. Ключ выплаты не содержит клинику: иначе один пациент мог бы получить несколько выплат за один месяц. Если в его строках есть один непустой представитель, вся месячная сумма относится к этому представителю. Это рабочее допущение, поскольку отдельной суммы оплаты, закреплённой за представителем, в задании нет. Если есть несколько разных представителей за один месяц, расчёт останавливается с ошибкой, а не выбирает одного случайно. Смена возрастной категории внутри месяца также требует отдельного решения.

Порог сравнивается строго через «больше», а не «больше или равно». При 100 000 рублей в июле и 120 000 рублей в августе или сентябре выплаты нет. Оплаты разных пациентов и разных месяцев между собой не складываются для достижения порога.

## 4. Автоконсолидация Power Query

В готовой книге запросы встроены. Исходный M-код сохранён отдельно в `Section1.m`. Начальная строка `section Section1;` обозначает раздел. Выражения `shared` объявляют запросы и функции. В редакторе Excel каждая такая сущность отображается отдельно.

Параметр `SourceFolder` читает именованную ячейку книги. Функция `Folder.Contents` получает файлы непосредственно из выбранной папки. Фильтр оставляет файлы с префиксом `EKMS_` и расширением `.xlsx`. Подпапки и итоговая книга в консолидацию не включаются.

Функция `ReadFile` открывает каждый файл через `Excel.Workbook`, выбирает лист `EKMS`, повышает первую строку до заголовков и нормализует названия столбцов. После этого оставляет поля, необходимые для задания, и добавляет имя файла и номер строки. Затем `Table.Combine` объединяет подготовленные таблицы по названиям колонок. Это защищает от сдвигов, когда в одной выгрузке есть дополнительные поля, а в другой их нет.

Важно различать «Добавить запросы» и «Объединить запросы». Добавление кладёт строки одного набора под строки другого. Объединение сопоставляет таблицы по ключу и присоединяет столбцы. В этом задании для месячных выгрузок требуется добавление строк.

Если делать с нуля через интерфейс Excel: создай пустую книгу, выбери «Данные → Получить данные → Из файла → Из папки», укажи папку с тремя выгрузками, затем «Преобразовать данные». Выбери нужные файлы, открой содержимое листов EKMS, подними заголовки и добавь таблицы. В книге уже подготовлен вариант с функцией чтения каждого файла: он проще переносит различия дополнительных колонок.

## 5. Очистка и типы

Текст очищается от непечатаемых символов, неразрывных и лишних обычных пробелов. Фамилии представителей не переводятся автоматически в другой регистр: задача не требует менять написание, а механическое преобразование может испортить составные имена.

ID пациента хранится как текст. Возраст — десятичное число. Компенсация — денежное число. Дата услуги — дата. Для строковых чисел применяется культура `ru-RU`, поэтому запись `5012,7` читается как 5012,70. В Python сумма проверяется через `Decimal`, чтобы избежать накопления ошибок двоичной арифметики.

Пустая компенсация не заменяется нулём. Пустые ID, возраст и даты не превращаются в корректные записи: запрос сообщает об ошибке. Полностью пустые строки пропускаются. Нулевой платёж при этом остаётся реальным значением.

В исходной таблице услуг не удаляются повторы по одному ID. Повторная строка пациента может быть другой услугой и влиять на месячную оплату. Без идентификатора операции удалять совпадающие по пациенту и сумме строки опасно. Удаление повторов применяется только в отдельной подготовке для подсчёта уникальных пациентов, где платежи не суммируются.

## 6. Вычисляемые колонки

Возрастная категория в пользовательском столбце Power Query:

```powerquery
if [возраст] >= 18 then "взрослые" else "дети"
```

Канал после очистки поля представителя:

```powerquery
if [представитель] <> "" then "от Агентов" else "Реклама"
```

Месяц услуги:

```powerquery
Date.ToText([дата услуги], "yyyy-MM")
```

В полном запросе отдельно обрабатываются исходные `null` и некорректные значения. Короткие выражения выше объясняют именно бизнес-логику.

## 7. Уникальные пациенты и настоящая сводная

Сначала запрос «Уникальные» выбирает четыре поля: месяц, клиника услуги, канал, ID пациента. Затем `Table.Distinct` оставляет каждую такую комбинацию один раз. Например, два визита одного пациента в одну клинику по одному каналу в августе дают одну строку. Визит в другую клинику создаёт отдельную строку — это требуется для показателя каждой клиники.

После такой подготовки обычное «Количество по id пациента» в сводной равно числу уникальных пациентов внутри её ячейки. Поэтому не требуется отдельная модель данных и функция Distinct Count. В готовом XLSX есть объект PivotTable с кэшем, а не только внешне похожая таблица.

Настройка сводной вручную: выдели таблицу `UniquePatients`, выбери «Вставка → Сводная таблица», добавь «клиника услуги» и «Канал привлечения» в строки, «Месяц» — в столбцы, «id пациента» — в значения и выбери «Количество». Для читабельности включи табличную форму отчёта. Не добавляй сумму ID.

Общие итоги сводной отключены. Один пациент может посещать разные клиники или попадать в разные каналы: сумма групп может быть больше числа людей по сети. Число пациентов за период рассчитывается отдельно через разные ID всей ЕКМС. В демонстрационном примере специально есть пациент, посетивший две клиники за месяц, и пациент, встречающийся в двух месяцах.

## 8. Расчёт вознаграждения

Запрос «ПациентМесяц» группирует ЕКМС по месяцу и ID пациента. В каждой группе он суммирует компенсации, определяет представителя и возрастную категорию и считает число исходных строк. Затем применяет правила выплаты.

| Месяц | Возраст | Условие по месячной сумме | Выплата за пациента |
| --- | --- | --- | --- |
| Июль 2024 | Только дети | Строго больше 100 000 ₽ | 5 000 ₽ |
| Август 2024 | Любая категория | Строго больше 120 000 ₽ | 8 000 ₽ |
| Сентябрь 2024 | Любая категория | Строго больше 120 000 ₽ | 8 000 ₽ |

Во всех случаях требуется представитель. Это фиксированная сумма за подходящего пациента, а не процент от оплаты и не выплата за каждые 100 или 120 тысяч рублей.

Пример: в августе пациент оплатил две услуги на 70 000 и 60 000 рублей. Месячная сумма — 130 000 рублей, поэтому представитель получает один раз 8 000 рублей. При проверке каждой строки отдельно обе суммы оказались бы ниже порога и выплата была бы ошибочно нулевой. При начислении 8 000 на каждую услугу после группировки получилось бы ошибочно 16 000.

На листе «Пациент месяц» столбец F содержит формулу с проверками месяца, категории и суммы. Формулы в XLSX хранятся с английскими именами функций, Excel отображает их в языке установленной версии. Основные функции: `IF` — выбор условия, `AND` — выполнение всех условий, `OR` — хотя бы одного. На листе «Вознаграждения» `SUMIFS` суммирует выплаты из расчётной таблицы по представителю и месяцу. Возле каждой суммы можно проверить исходные строки пациента.

При обновлении Power Query заменяет результаты таблиц значениями, вычисленными по той же логике M. Актуальные итоги также загружаются запросами, поэтому они не зависят от фиксированной длины формульных диапазонов первоначальной книги. Формулы первоначальной версии сохранены для разбора расчёта.

## 9. Как обновить книгу

1. Сохрани книгу и выгрузки на компьютере. Для полной локальной версии рядом уже есть папка «Выгрузки». Для публичного примера три синтетических файла можно положить в одну папку.
2. Открой «Параметры» и запиши в B2 полный путь к этой папке. В демонстрационной книге указан шаблон `C:\EKMS_DEMO` — его нужно заменить своим путём.
3. Открой «Данные → Запросы и подключения». В книге есть запросы ЕКМС, Уникальные, ПациентМесяц, Вознаграждения, ИтогиМесяцев и ИтогиПериода, а также вспомогательные функции и параметр.
4. Выбери «Данные → Обновить всё» и дождись завершения запросов. Если Excel запросит уровень конфиденциальности для локальных источников, укажи подходящий уровень, сохраняя проверку конфиденциальности включённой.
5. После загрузки таблицы «Уникальные» щёлкни сводную и нажми «Обновить». Этот отдельный шаг нужен, чтобы сводная читала уже обновлённый источник.
6. Сопоставь число строк и компенсации с выгрузками, затем проверь итог выплат и несколько пациентов вручную.

Правила задания определены для июля, августа и сентября 2024 года. Для другого месяца нельзя автоматически предполагать прежние условия: в запросе выплаты предусмотрена ошибка для представителя из месяца без заданного правила. При расширении периода нужно явно добавить политику нового месяца и колонки отчёта представителей.

Если установленная версия Excel не показывает встроенные запросы, исходный код можно восстановить вручную: создай пустые запросы с именами после `shared`, перенеси выражение справа от `=` до завершающей точки с запятой в «Расширенный редактор». Для SourceFolder создай именованную ячейку `SourceFolder` со ссылкой на «Параметры» B2. Функции и параметр оставь как подключения, таблицы загрузи на соответствующие листы. Это запасной способ восстановления, а не выполненная проверка обновления.

## 10. Что проверено и что требует Excel

Автоматическая сверка проверяет число строк, суммы компенсаций, суммы пациента за месяц, выплаты, уникальность внутри групп и сохранённые значения формул. Дополнительно проверяются кэш PivotTable, шесть подключений, соответствие встроенного M отдельному файлу, целостность XML и внутренних ссылок XLSX.

Тесты правил включают возраст 17,99 и 18, точное равенство порогу и превышение на копейку, взрослого пациента в июле, отсутствие представителя, пробельное значение и достижение порога несколькими услугами. Синтетический пример даёт выплаты 5 000, 16 000 и 16 000 рублей по месяцам, всего 37 000 рублей. Эти суммы относятся только к демонстрации.

Движок Microsoft Excel в среде подготовки отсутствует. Запросы встроены в формат XLSX и проверены по структуре, но запуск M, обновление подключений и интерактивное поведение сводной в настольном Excel здесь не проверялись. Отчёт аудита отделяет успешные проверки данных от этого незапущенного этапа. После первого открытия и обновления книги нужно убедиться, что Excel не сообщает о восстановлении содержимого и суммы сохранились.

## 11. Как объяснить решение на собеседовании

«Я объединила месячные выгрузки Power Query по названиям полей, сохранив имя файла и номер строки для проверки. Возраст сравнивала без округления, а канал определяла по наличию представителя. Для сводной сначала оставила уникальные комбинации месяца, клиники, канала и пациента, затем посчитала их обычной сводной. Для вознаграждения отдельно сложила оплаты пациента за месяц и один раз применила правило соответствующего месяца. Итоги по представителю получила суммированием этих выплат».

Если спросят, почему нельзя удалить повторы по ID сразу: это уничтожило бы услуги и занизило оплаты. Если спросят, почему сумма сводной не равна числу людей по сети: пациент может входить в несколько групп. Если спросят, почему не использован столбец «источник»: канал явно задан наличием представителя. Если спросят про возвраты: отрицательные суммы нужно включать в нетто-оплату при подтверждённой такой трактовке поля, а не удалять их автоматически. В предоставленных исходных выгрузках отрицательных компенсаций нет.

Не представляй незапущенное обновление как выполненную проверку Excel. Корректная формулировка: «Расчёты и структура книги сверены программно, обновление в установленной версии Excel нужно подтвердить отдельно».

## 12. Словарь

**Гранулярность** — что обозначает одна строка таблицы: услуга, пациент за месяц или уникальное посещение клиники. **Ключ** — поля, по которым отличаем записи или создаём группы. **Консолидация** — сбор однотипных выгрузок в одну таблицу. **Группировка** — получение одной строки на группу с суммой или количеством. **Уникальный пациент** — один ID в пределах выбранного контекста. **Power Query** — последовательность шагов чтения и преобразования данных. **M** — язык этих шагов. **Кэш сводной** — сохранённый набор данных для PivotTable; обновляется из таблицы источника. **Проверка порога** — сравнение месячной суммы с условием строго больше установленной величины.
